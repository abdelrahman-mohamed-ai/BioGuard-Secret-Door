# BioGuard Fingerprint Lab Fix Report

Date: 2026-11-19

Scope: fingerprint lab only. Face recognition, voice verification, voice commands, door authentication, enrollment, notebooks, datasets, users, permissions, and trained model artifacts were not changed.

## 1. Exact root cause

The existing fingerprint model and research extractor were compatible. The artifact expects a 30-dimensional pair vector, and the unchanged research pipeline produces that vector from a 29-dimensional fingerprint vector plus cosine similarity.

The defect was in the lab integration:

- `POST /fingerprint` used a synchronous full-page form with no browser preview or repeat-upload flow.
- The route returned an HTML page for every outcome and caught all failures with a generic `Scan rejected: ...` message.
- There was no structured error code for missing, invalid, corrupt, or unreadable images.
- The page did not display the real preprocessing stages or model metadata.
- The route did not validate the loaded artifact's feature dimensions and gallery references before inference.

The model itself was not replaced or bypassed. The fixed adapter delegates the actual prediction to the unchanged `fingerprint_research.identify_upload` function after validating the trusted artifact and generating display-only visualizations from the same preprocessing stages.

## 3. Model and feature dimensions

Loaded directly from `model/fingerprint_model.joblib`:

| Item | Actual value |
|---|---:|
| Model name | SVM |
| Dataset metadata | SOCOFing |
| Fingerprint feature vector | 29 |
| Pair feature vector | 30 |
| Demo gallery references | 25 |
| Threshold | 0.8077645335329597 |

The unchanged feature path is:

`image → grayscale → resize 128×128 → histogram equalization → Sobel orientation/magnitude features + uniform LBP histogram + statistics → 29-D vector → absolute pair difference + cosine → 30-D SVM input → positive-class probability → score >= threshold`

The adapter validates that the model input is 30-D and every gallery reference is a finite 29-D vector before accepting the artifact.

## 4. Real prediction results

These results were generated by loading the existing artifact and processing real files from `fingerprint_data/selected/`. No prediction was simulated.

| Input category | Decision | Score | Threshold |
|---|---|---:|---:|
| Gallery real image | MATCH | 0.9935615557 | 0.8077645335 |
| Same-finger synthetic altered probe | MATCH | 0.9943964286 | 0.8077645335 |
| Real out-of-gallery image | NO MATCH | 0.3335720332 | 0.8077645335 |

For a pair-level negative diagnostic, the same known altered query was compared against the 24 wrong gallery references. All 24 were below threshold; the largest wrong-reference score was `0.0008472461`. This is a reference-level diagnostic, not a claim of unknown-person accuracy.

The artifact metadata explicitly limits the research experiment: synthetic altered probes are not independent captures, and the model is not a real-time scanner or anti-spoofing system.

## 5. Upload and API behavior

The route now accepts `.png`, `.jpg`, `.jpeg`, and `.bmp` uploads. Uploaded media is stored only in a randomized private runtime directory and removed in the `finally` block after processing.

The browser sends `Accept: application/json` and receives the actual model fields, including:

- `match` and `decision`
- `score` and `threshold`
- model name and gallery count
- feature and pair dimensions
- original, grayscale, Sobel, and LBP PNG data URLs

Stable failure codes include:

- `NO_FILE`
- `INVALID_EXTENSION`
- `EMPTY_UPLOAD`
- `IMAGE_DECODE_FAILED`
- `MODEL_LOAD_FAILED`
- `MODEL_INCOMPATIBLE`
- `VERIFICATION_FAILED`
- `FINGERPRINT_PROCESSING_FAILED`

The selected file remains available in the browser after an error so the user can retry or choose another file without a page reload.

## 8. Remaining limitations

- This is an offline academic upload lab; no live fingerprint scanner was added.
- The 25-reference demo gallery is a research demonstration, not a complete employee database.
- The model's SOCOFing altered probes are not independent live captures.
- One out-of-gallery image is useful as a smoke test but cannot establish robust unknown-rejection performance.
- No anti-spoofing or production biometric-security claim is made.
- The browser camera/microphone and door flows were intentionally not modified.
